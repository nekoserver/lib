#インシデント主な兆候diag の該当チェック切り分け・次手
1VM の意図せぬ再起動全サービスが同時に若い常駐物: VM 稼働時間（WARN）、tailscaled の開始時刻開始時刻で再起動と断定する。tailscaled と Bridge の復帰を続けて確認
2tailscaled 停止・オフラインtailnet から届かない常駐物: tailscaled（FAIL）プロセス不在なら bootstrap 経路（nixwrap / boot-trigger）を確認。確認自体が起動しうる CLI は使わない
3API Bridge 無応答POST が返らない、:8080 無応答常駐物: API Bridge /health（FAIL）プロセスと待ち受けポートを確認
4Bridge の滞留・遅延応答が数分かかる、後続が詰まる常駐物: /health 応答時間（WARN）、ジョブ: キューの滞留（WARN）単一エージェントの直列処理が上限。長い依頼が先行していないか queue/done を見る
5ブリッジの安全停止（504）特定の依頼だけ 600s タイムアウト（diag 外）/health は OK のままジョブ結果ファイルで未応答の有無を確認。サーバ側に検知ルールは無い
6メモリ枯渇・OOMプロセスが落ちる、全体が重いメモリ: 空きメモリ（WARN/FAIL）、スワップ、OOM killer、RSS 上位RSS 上位が想定内か。この VM では大半の使用量が内訳に出ない点に注意
7ディスク枯渇書き込み失敗、ビルド失敗ディスク: 使用率（WARN/FAIL）、ジャーナル使用量、workspace サイズ対象マウントの大きいディレクトリを du で追う
8inode 枯渇空き容量があるのに作れないディスク: inode 使用率（WARN/FAIL）小ファイルの大量生成先を探す
9負荷過多何をしても遅いCPU: ロードアベレージ（WARN/FAIL）、CPU 上位、PSI上位プロセスが想定内か。セル配分（1.5 コア）比で見る
10ゾンビ・FD 枯渇起動失敗、too many open filesプロセス: ゾンビ（WARN）、ファイルハンドル（WARN）親プロセスの回収漏れ、リークする常駐物の特定
11ネットワーク不通・DNS名前が引けない、外へ出られないネットワーク: デフォルト経路、DNS 解決、待ち受けポート数、TIME_WAIT外向きはプロキシ経由が前提。DNS は参考値、経路とポートを先に見る
12時刻ずれ署名検証や有効期限で落ちる時刻: NTP 同期、現在時刻Webhook の ±300s 窓やトークン期限への影響を先に疑う
13未 push 成果物の喪失リスクVM 再起動で作業が消えるgit: 未 push コミット（WARN）、未コミット変更（WARN）push は承認手続き付き。対象は git-heads.sh で特定する
14秘密情報の権限過大トークンが他者可読権限: ブリッジトークンの権限（FAIL は 600 以外）値には触らず権限だけ直す
15muse 未認証SDK のターンが authRequired（diag 外）sdk-health.sh / sdk-ask.sh の結果serve プロセスから見える認証が要る。サインインは本人の操作
16:auto-review 不可用profile_not_applied で弾かれる（diag 外）sdk-profiles.sh で available を確認一覧で available でも実行時に弾かれることがある。キー設定の有無を確認
17SDK と本体の版ずれSDK が妙なエラーになる（diag 外）sdk-health.sh の版表示sdk-setup.sh で同版を入れ直す
18muse デーモン未起動--listen 前提のクライアントが繋げない常駐物: muse デーモン（WARN）spawn 方式だけで足りるなら正常。常駐が要る場合は sdk-serve.sh start
19systemd ユニット失敗一部機能だけ止まっている常駐物: systemd 失敗ユニット（WARN）対象ユニットの journal を見る
20ログの異常多発・肥大error が急増、ディスク圧迫ログ: 直近1時間の error ログ（WARN）、panic/segfault、ジャーナル使用量エラーの初出時刻と契機（再起動、push、設定変更）を突き合わせる
