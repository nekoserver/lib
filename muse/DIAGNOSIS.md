# 診断マトリックス

`diag.sh`（読み取り専用、全33項目）の結果を、想定インシデントへ対応付ける表。
ダッシュボード用には同じ表を `dashboard/matrix.html` にも置いている。

見方:

- `diag.sh` の終了コード: 0 = 異常なし、1 = WARN あり、2 = FAIL あり
- `diag.sh -s` は件数と WARN/FAIL のみ。ダッシュボードの診断区画はこれ
- `DIAG_QUICK=1` で du とログ走査を省く（数百 ms で終わる）

| # | インシデント | 主な兆候 | diag の該当チェック | 切り分け・次手 |
|---|---|---|---|---|
| 1 | VM の意図せぬ再起動 | 全サービスが同時に若い | 常駐物: VM 稼働時間（WARN）、tailscaled の開始時刻 | 開始時刻で再起動と断定する。tailscaled と Bridge が復帰しているか続けて確認 |
| 2 | tailscaled 停止・オフライン | tailnet から届かない | 常駐物: tailscaled（FAIL） | プロセス不在なら bootstrap 経路（nixwrap / boot-trigger）を確認。開始時刻の付け忘れに注意（確認自体が起動しうる CLI は使わない） |
| 3 | API Bridge 無応答 | POST が返らない、:8080 無応答 | 常駐物: API Bridge /health（FAIL） | プロセスとポート（ネットワーク: 待ち受けポート数）を確認。サーバ再起動はサーバ側手順で |
| 4 | Bridge の滞留・遅延 | 応答が数分かかる、後続が詰まる | 常駐物: /health 応答時間（WARN）、ジョブ: キューの滞留（WARN） | 単一エージェントの直列処理が上限。長い依頼が先行していないか done/queue の中身を見る |
| 5 | ブリッジの安全停止（504） | 特定の依頼だけ 600s タイムアウト | （diag 外）/health は OK のまま | ジョブ結果ファイルで未応答の有無を確認。サーバ側に検知ルールは無い |
| 6 | メモリ枯渇・OOM | プロセスが落ちる、全体が重い | メモリ: 空きメモリ（WARN/FAIL）、スワップ使用率、OOM killer、RSS 上位 | RSS 上位のプロセスが想定内か。この VM では大半の使用量が内訳に出ない点に注意 |
| 7 | ディスク枯渇 | 書き込み失敗、ビルド失敗 | ディスク: 使用率（WARN/FAIL）、ジャーナル使用量、workspace サイズ | 対象マウントの大きいディレクトリを du で追う。ジャーナル肥大なら真空処理は運用判断 |
| 8 | inode 枯渇 | 空き容量があるのに作れない | ディスク: inode 使用率（WARN/FAIL） | 小ファイルの大量生成先（キャッシュ、ノード modules 等）を探す |
| 9 | 負荷過多 | 何をしても遅い | CPU: ロードアベレージ（WARN/FAIL）、CPU 上位、PSI | 上位プロセスが想定内か。セル配分（1.5 コア）比で見る |
| 10 | ゾンビ・FD 枯渇 | 起動失敗、too many open files | プロセス: ゾンビ（WARN）、ファイルハンドル（WARN） | 親プロセスの回収漏れ、リークする常駐物の特定 |
| 11 | ネットワーク不通・DNS | 名前が引けない、外へ出られない | ネットワーク: デフォルト経路、DNS 解決、待ち受けポート数、TIME_WAIT | 外向きはプロキシ経由が前提。DNS は参考値として扱い、経路とポートを先に見る |
| 12 | 時刻ずれ | 署名検証や有効期限で落ちる | 時刻: NTP 同期、現在時刻 | ずれている場合は Webhook の ±300s 窓やトークン期限への影響を先に疑う |
| 13 | 未 push 成果物の喪失リスク | VM 再起動で作業が消える | git: 未 push コミット（WARN）、未コミット変更（WARN） | push は承認手続き付き。件数と対象リポジトリを git-heads.sh で特定する |
| 14 | 秘密情報の権限過大 | トークンが他者可読 | 権限: ブリッジトークンの権限（FAIL は 600 以外） | 値には触らず権限だけ直す。状態ディレクトリの権限も併せて確認 |
| 15 | muse 未認証 | SDK のターンが authRequired | （diag 外）sdk-health.sh / sdk-ask.sh の結果 | serve プロセスから見える認証が要る。サインインは本人の操作 |
| 16 | :auto-review 不可用 | profile_not_applied で弾かれる | （diag 外）sdk-profiles.sh で available を確認 | プロファイル一覧で available でも、自動レビュアーが使えないと実行時に弾かれる。キー設定の有無を確認 |
| 17 | SDK と本体の版ずれ | SDK が妙なエラーになる | （diag 外）sdk-health.sh の版表示 | 版を揃え直す（sdk-setup.sh が同版を入れ直す） |
| 18 | muse デーモン未起動 | --listen 前提のクライアントが繋げない | 常駐物: muse デーモン（WARN） | spawn 方式だけで足りるなら正常。常駐が要る場合は sdk-serve.sh start |
| 19 | systemd ユニット失敗 | 一部機能だけ止まっている | 常駐物: systemd 失敗ユニット（WARN） | 対象ユニットの journal を見る |
| 20 | ログの異常多発・肥大 | error が急増、ディスク圧迫 | ログ: 直近1時間の error ログ（WARN）、カーネルの panic/segfault、ディスク: ジャーナル使用量 | エラーの初出時刻と契機（再起動、push、設定変更）を突き合わせる |
